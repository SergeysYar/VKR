# VKR PointCloud Suite

Подробная документация проекта по синтетической генерации промышленных сцен, распознаванию инженерных объектов в облаках точек, сегментации и восстановлению поверхности.

## 1. Назначение проекта

Проект объединяет в одном программном комплексе два рабочих контура:

1. Искусственное создание данных:
   генерация промышленной сцены, получение LiDAR-облака, размещение объектов и сохранение результатов.
2. Аналитика готовых облаков:
   распознавание объектов, дообучение моделей, сегментация объекта на части, восстановление поверхности и экспорт OBJ.

Ключевая цель: получить воспроизводимый end-to-end pipeline для демонстрации и практической обработки облаков точек инженерных объектов.

## 2. Состав репозитория

Основные директории:

- `lesson5/` — прикладная часть (UI, pipeline, модели PointNet, обучение).
- `synthetic_factory/` — генератор промышленной сцены.
- `laserSensing/` — алгоритмы оптимального планирования LiDAR-станций.
- `Surface-reconstructore/` — внешний модуль реконструкции (поддерживается через интеграцию в `lesson5/SurfaceReconstructor.py`).

Ключевые файлы:

- `run_showcase_uv.ps1` — единая точка запуска приложений через `uv`.
- `lesson5/factory_tabs_app.py` — единое приложение с двумя вкладками.
- `lesson5/factory_synthetic_builder_app.py` — вкладка/приложение генерации и размещения.
- `lesson5/factory_analysis_app.py` — вкладка/приложение анализа готовых облаков.
- `lesson5/factory_showcase_pipeline.py` — backend-пайплайн (основная бизнес-логика).
- `lesson5/engineering_classifier/core.py` — обучение/инференс PointNet через PyTorch Lightning.
- `lesson5/dataset.py` — загрузка/нормализация `.ply`, санитизация путей.
- `pyproject.toml` — зависимости и конфигурация проекта для `uv`.

## 3. Архитектура

Проект реализован как слой интерфейса + слой пайплайна:

1. UI-слой (`Streamlit`):
   - собирает параметры пользователя;
   - визуализирует облака/OBJ;
   - отображает логи обучения и статусы.
2. Pipeline-слой (`factory_showcase_pipeline.py`):
   - генерирует сцену и облака;
   - выполняет размещение объектов;
   - запускает распознавание/сегментацию/восстановление;
   - сохраняет артефакты (PLY/OBJ/JSON).
3. ML-слой (`engineering_classifier` + `model.py`):
   - PointNet-модель;
   - обучение и инференс;
   - подбор чекпоинтов и экспорт предсказаний.

По сути используется оркестраторный подход:
интерфейс оркестрирует вызовы независимых функций пайплайна с явными входами/выходами.

## 4. Установка и окружение (uv)

Требования:

- Windows + PowerShell (основной рабочий сценарий).
- Python `>= 3.12`.
- Установленный `uv`.

Создание окружения и установка зависимостей:

```powershell
cd C:\_Work\VKR
uv venv .venv
uv sync --project .
```

Запуск через скрипт:

```powershell
powershell -ExecutionPolicy Bypass -File .\run_showcase_uv.ps1 -App tabs -Port 8513
```

Где `-App`:

- `tabs` — единое приложение с двумя вкладками (рекомендуется).
- `builder` — только генерация/размещение.
- `analysis` — только анализ готовых облаков.
- `showcase` — legacy-версия монолитного интерфейса.

Опционально:

- `-SkipSync` — пропустить `uv sync`, если зависимости уже установлены.

Прямой запуск без скрипта:

```powershell
uv run --project . streamlit run lesson5/factory_tabs_app.py --server.headless true --server.port 8513
```

## 5. Решение проблемы ExecutionPolicy

Если PowerShell блокирует запуск `.ps1`:

```powershell
.\run_showcase_uv.ps1 : ... выполнение сценариев отключено ...
```

используйте один из вариантов:

1. Разовый запуск:
```powershell
powershell -ExecutionPolicy Bypass -File .\run_showcase_uv.ps1
```
2. Для текущей сессии:
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\run_showcase_uv.ps1
```

## 6. Вкладки и пользовательские сценарии

## 6.1 Конструктор синтетических облаков

Файл: `lesson5/factory_synthetic_builder_app.py`

Блок 1. Подготовка промышленной сцены:

1. Генерация сцены в 2 шага:
   - шаг 1: построение и предпросмотр `OBJ` сцены;
   - шаг 2: генерация LiDAR-облака по подтвержденной сцене.
2. Параметры:
   - `Seed`, размеры сцены, количество комнат, высота;
   - выбор биомов комнат;
   - плотность LiDAR (`0.25..8.0`);
   - опция использования `laserSensing` для расстановки станций.
3. Поддерживается загрузка уже готового облака сцены (`.ply`) и метаданных (`.json`).
4. Есть сохранение облака сцены в произвольный путь.

Блок 2. Размещение объектов:

1. Объекты добавляются по одному в очередь:
   - путь к конкретному `.ply`;
   - тип объекта.
2. Для очереди доступно:
   - добавление;
   - удаление по номеру;
   - очистка.
3. После запуска размещения:
   - формируется объединенное облако;
   - строится список обнаружений по комнатам;
   - сохраняются PLY/JSON-артефакты.
4. Есть отдельная кнопка сохранения объединенного облака.

## 6.2 Аналитика готовых облаков

Файл: `lesson5/factory_analysis_app.py`

Режимы:

1. Демо-режим:
   - принимает заранее размеченное облако;
   - показывает сценарий:
     распознавание (без меток) -> сегментация -> восстановление -> OBJ;
   - работает без `.ckpt` (с fallback-логикой);
   - при включенном демо скрывает ручные блоки анализа.
2. Ручной режим:
   - загрузка готового облака;
   - распознавание объектов;
   - дообучение модели распознавания;
   - дообучение модели сегментации;
   - сегментация выбранного объекта;
   - восстановление поверхности.

Во многих полях доступно два способа ввода:

1. Ввести путь вручную.
2. Выбрать файл через диалог (`file_uploader`).

## 7. Модели и веса

Разделяются два типа весов:

1. Распознавание объектов (recognition).
2. Сегментация частей объекта (segmentation).

Рекомендуемая структура:

- `D:\vesa\recognition\<имя_модели>\checkpoints\...`
- `D:\vesa\segmentation\<тип_объекта>\checkpoints\...`

В интерфейсе реализован автопоиск последнего `.ckpt` по времени модификации.

## 8. Форматы входных данных

Базовый формат `.ply`:

- ASCII PLY;
- минимум координаты `x y z`;
- для задач с метками желательно 4-й столбец с целочисленной меткой.

Поддержка в загрузчике:

1. Если есть только `x y z`, метки могут быть пустыми/нулевыми.
2. Если длина меток не совпадает с длиной точек, выполняется выравнивание.
3. Перед чтением выполняется санитизация пути:
   удаляются невидимые Unicode-символы управления (`\u202a`, `\ufeff` и т.д.).

## 9. Форматы датасетов для дообучения

## 9.1 Дообучение распознавания (`label_mode=folder_name`)

Структура:

```text
dataset_root/
  valve/
    *.ply
  pump/
    *.ply
  flange/
    *.ply
```

Каждая папка — отдельный класс объекта.

## 9.2 Дообучение сегментации (`label_mode=per_point`)

Структура:

```text
dataset_root/
  *.ply
```

или рекурсивно по подпапкам, где в каждом `.ply` должны быть корректные метки частей.

Важно:

1. Метки должны быть неотрицательными.
2. `num_classes` должен покрывать максимальную метку.
3. В проекте есть автокоррекция:
   если введенное `num_classes` меньше требуемого, значение автоматически увеличивается.

## 10. Что сохраняется и где

Обычно артефакты пишутся в `lesson5/factory_demo_runs/` (или в путь из UI).

Типичные файлы:

1. Облако сцены:
   `factory_cloud.ply` + `factory_cloud_metadata.json`.
2. OBJ сцены:
   `industrial_scene.obj`.
3. Совмещенное облако сцена+объекты:
   `factory_objects_combined.ply` + `placement_metadata.json`.
4. Распознанные метки:
   `recognized_labels.ply`.
5. Восстановление поверхности:
   `*_part_XX_*.ply`, `*_reconstruction_combined.ply`, `*_reconstruction.obj`.

## 11. Свойства PLY, которые пишет pipeline

## 11.1 Сцена (`_write_factory_cloud_ply`)

Поля вершины:

- `x, y, z`
- `label`
- `room_index`

## 11.2 Комбинированное облако (`_write_combined_ply`)

Поля вершины:

- `x, y, z`
- `source` (0 = сцена, 1 = добавленный объект)
- `factory_label`
- `object_type`
- `object_instance`
- `part_label`
- `room_index`

## 12. Реконструкция поверхности

Реализовано два backend-подхода:

1. `surface_reconstructor`:
   использование `lesson5/SurfaceReconstructor.py` (приоритетный модуль по флажку).
2. `lightweight_surface_reconstructor`:
   встроенный геометрический fallback.

Текущие особенности:

1. Добавлен консервативный режим восстановления (меньше агрессивных достроек).
2. Добавлено огрубление мешей (decimation).
3. При экспорте OBJ есть fallback `mesh_from_points`:
   если готовых mesh-файлов нет, OBJ строится из итогового облака точек.

В результате в `obj_export['mode']` возможны:

- `mesh`
- `mesh_from_points`
- `points_only` (самый крайний fallback)

## 13. Основные API-функции pipeline

Файл: `lesson5/factory_showcase_pipeline.py`

Ключевые функции:

1. `generate_factory_scene_preview(...)` — сгенерировать и сохранить только OBJ/метаданные.
2. `generate_factory_cloud(...)` — получить LiDAR-облако сцены.
3. `place_object_files_in_factory_cloud(...)` — разместить очередь объектов.
4. `recognize_cloud_with_model(...)` — инференс распознавания по checkpoint.
5. `finetune_recognition_model(...)` — дообучение распознавания.
6. `finetune_object_model(...)` — дообучение сегментации/объектной модели.
7. `classify_object_parts(...)` — сегментация одного объекта.
8. `reconstruct_object_surfaces(...)` — восстановление поверхности по сегментам.
9. `export_reconstruction_obj(...)` — экспорт результата в OBJ.

## 14. Частые ошибки и решения

## 14.1 TensorBoard не найден

Ошибка:

```text
ModuleNotFoundError: Neither `tensorboard` nor `tensorboardX` is available
```

Решение:

```powershell
uv sync --project .
```

или точечно:

```powershell
uv pip install tensorboard
```

Примечание:
в коде есть fallback на CSV-логгер, но лучше иметь `tensorboard`.

## 14.2 `IndexError: Target N is out of bounds`

Причина:
`num_classes` меньше максимальной метки в датасете.

Решение:

1. Проверить метки в данных.
2. Увеличить `num_classes`.
3. Использовать встроенную автокоррекцию (уже реализована в `finetune_object_model`).

## 14.3 Ошибка пути с невидимым символом

Ошибка вида:

```text
OSError: [Errno 22] Invalid argument: '\u202aC:\...'
```

Решение:

1. Вводить путь заново вручную.
2. Использовать выбор через диалог.
3. Использовать текущие функции загрузки, где включена `sanitize_filesystem_path`.

## 14.4 PowerShell блокирует `.ps1`

См. раздел 5 (ExecutionPolicy Bypass).

## 14.5 Конфликт импорта `PointNetSegmentationLightning` из `laserSensing/model`

В проекте это уже обходится в `engineering_classifier/core.py`:
класс грузится принудительно из локального `lesson5/model.py`.

## 15. Производительность и практические рекомендации

1. Для быстрой работы держите `lidar_density` в диапазоне `1.0..3.0`.
2. Значения `5.0+` дают очень плотные облака, но заметно увеличивают время/память.
3. Для демо используйте:
   - заранее размеченное облако;
   - минимальный порог точек на сегмент около `20..45`;
   - включенный `SurfaceReconstructor` в демо.
4. Для обучения на CPU уменьшайте `batch_size` при нехватке памяти.

## 16. Быстрый старт по задачам

## 16.1 Сгенерировать сцену и разместить объекты

1. Запустить `tabs` или `builder` приложение.
2. На вкладке конструктора:
   - шаг 1: сгенерировать OBJ сцены;
   - шаг 2: построить LiDAR-облако;
   - добавить `.ply` объектов в очередь;
   - нажать размещение;
   - сохранить комбинированное облако.

## 16.2 Проанализировать готовое облако

1. Запустить `tabs` или `analysis` приложение.
2. Загрузить облако.
3. Выполнить распознавание.
4. При необходимости дообучить распознавание.
5. Выполнить сегментацию целевого объекта.
6. Запустить восстановление и экспорт OBJ.

## 16.3 Прогнать демонстрацию

1. Включить флажок демо-режима.
2. Загрузить заранее размеченное `.ply`.
3. Запустить демо-сценарий.
4. Проверить шаги и итоговый OBJ.

## 17. Примечания для разработки

1. Проект может запускаться как в составе вкладок (`factory_tabs_app.py`), так и отдельными приложениями.
2. Для совместимости с текущим рабочим процессом стоит использовать `run_showcase_uv.ps1`.
3. Временные файлы/логи (`_tmp_*`, `run_tabs_*.log`) не должны попадать в коммиты.

## 18. Технологический стек

Ниже перечислен фактический стек, который используется в текущей реализации проекта.

### 18.1 Язык и окружение

- Python `3.12+`
