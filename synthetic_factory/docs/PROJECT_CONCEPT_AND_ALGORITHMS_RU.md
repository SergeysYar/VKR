# Synthetic Factory: Концепция и алгоритмы

## 1. Главная идея проекта

Проект генерирует **сцену завода** как иерархический граф объектов (scene graph), после чего экспортирует все в единый OBJ.

Ключевая цель:
- получать воспроизводимые, параметрически управляемые сцены;
- разделять генерацию на независимые этапы;
- поддерживать разные функциональные зоны завода (биомы);
- собирать финальную геометрию в стандартный формат для Blender/MeshLab/CAD.

---

## 2. Базовая модель данных

### 2.1 Scene Graph

- `Scene` хранит корневые объекты.
- `SceneObject` содержит:
  - `id`, `type`;
  - `transform` (`position`, `rotation`, `scale`);
  - `mesh` (опционально);
  - `children` (иерархия).
- `AnchorPoint` используется для логичных привязок вторичных деталей (top/side/bottom).

Идея: вся сцена описывается как дерево объектов, где трансформации наследуются сверху вниз.

### 2.2 Геометрия

- `Mesh` хранит:
  - `vertices`;
  - `faces` (треугольники);
  - `normals` (опционально).
- Базовые операции:
  - `add_vertex`, `add_face`;
  - `merge`;
  - `transform(4x4 matrix)`;
  - `compute_normals`.

---

## 3. Пайплайн генерации сцены

Пайплайн разбит на этапы:

1. `ParameterSamplingStage`
2. `LayoutGenerationStage`
3. `RoomGenerationStage`
4. `SceneAssemblyStage`
5. `ExportStage`

Это делает систему модульной и удобной для расширения.

---

## 4. Алгоритмы по этапам

## 4.1 Parameter Sampling

Источник: `ParameterSet`.

Что делает:
- хранит параметры в виде `Parameter(name, value, min/max, distribution)`;
- поддерживает `uniform` и `normal`;
- поддерживает выражения (`"room_height": "room_size_max * 0.3"`);
- учитывает зависимости параметров через топологический порядок вычисления.

Алгоритм:
1. Построить граф зависимостей по выражениям.
2. Отсортировать параметры в порядке вычисления.
3. Для каждого параметра:
   - вычислить `value/min/max` (число или выражение);
   - выполнить сэмплинг по распределению;
   - записать результат в контекст.

Результат: конкретный набор чисел для текущего запуска.

---

## 4.2 Layout Generation (FactoryGenerator)

Поддерживаются два режима:
- `grid`;
- `perlin`.

### Grid layout

1. Вычислить сетку `rows x cols` под нужное число комнат.
2. Учесть ширину коридоров.
3. Для каждой ячейки вычислить:
   - центр комнаты;
   - базовую ширину/глубину.

### Perlin layout

1. Создать больше кандидатных слотов, чем итоговых комнат.
2. Для каждой ячейки вычислить `score` из Perlin noise.
3. Отобрать `N` комнат по score.
4. Если `connectivity_bias >= 0.5`, выбирать комнаты связным кластером.
5. Назначить итоговые размеры комнаты из score и aspect-вариации.

Итог: набор `RoomLayout` с координатами и размерами.

---

## 4.3 Назначение биомов

После layout, каждой комнате назначается биом.

Логика:
1. Выбрать главный `workshop` (крупнейшая или центральная из крупнейших).
2. Остальные комнаты получить по `cycle_order`.
3. Если `ensure_all_types=true`, цикл дополняется всеми биомами из реестра.

Дополнительно:
- к размерам комнаты применяется профиль биома (`size_multiplier`, `width_multiplier`, `depth_multiplier`);
- есть ограничения по минимальному/максимальному заполнению слота.

Итог: биомы различаются не только содержимым, но и геометрическим масштабом.

---

## 4.4 Высоты помещений

Текущая логика высоты:
1. Берется базовая `room_height` из параметров.
2. Применяется `height_multiplier` биома.
3. Для boiler учитывается минимум от высоты котла (`boiler_height * 1.2`).
4. Применяются ограничения профиля `min_height/max_height`.

Это убирает аномально высокие офисы и делает высоты реалистичными по функциям помещений.

---

## 4.5 Генерация комнаты (RoomGenerator)

Для каждой комнаты создаются:
- пол;
- потолок;
- 4 стены;
- дверные/оконные opening-объекты.

RoomGenerator отвечает за базовую оболочку помещения, без биом-специфичного оборудования.

---

## 4.6 Сборка сцены

После генерации комнат добавляются глобальные подсистемы:

1. `place_corridors`:
   - горизонтальные и вертикальные коридоры по всей сетке.

2. `place_factory_flow`:
   - центральный “spine”;
   - связующие участки от комнат к главной оси (логика единого завода).

3. `place_columns`:
   - колонны по шагу.

4. `place_beams`:
   - балки между колоннами по X/Y.

5. `place_machinery`:
   - биом-специфичные объекты внутри комнат.

---

## 4.7 Биом-специфичная генерация

Каждый биом — отдельный модуль (`workshop`, `boiler`, `control`, `electrical`, `laboratory`, `office`, `storage`, `maintenance`).

Каждый модуль задает:
- набор используемых примитивов;
- локальные правила;
- функцию `populate(room, add_object, settings)`.

Общий контракт:
1. Генератор передает размер и тип комнаты.
2. Биом размещает свое оборудование по собственному алгоритму.
3. Объекты добавляются в отдельную группу содержимого комнаты.

---

## 4.8 Auxiliary Generator (вторичные детали)

Назначение: увеличить реализм без перестройки основной структуры.

Алгоритм:
1. Найти primary-объекты биома.
2. Построить кандидатов дочерних объектов (auxiliary).
3. Выбрать anchor point (если нужен).
4. Проверить размещение:
   - в пределах родительского объема;
   - без пересечения с существующими sibling-деталями.
5. Привязать объект как child к родителю.

Управляется параметрами:
- `density`;
- `complexity`;
- биом-специфичными вероятностями/количествами.

---

## 4.9 Экспорт в OBJ

`ObjExporter` проходит по scene graph и делает:

1. Обход дерева с накоплением world matrix.
2. Клонирование mesh объекта.
3. Применение transform к вершинам.
4. Вычисление нормалей (если отсутствуют).
5. Запись `o`, `g`, `v`, `vn`, `f`.
6. Корректировка индексов через `vertex_offset`/`normal_offset`.

Итог: один OBJ-файл, где сохранены имена и группировка иерархии.

---

## 5. Воспроизводимость

Воспроизводимость обеспечивается через seed:
- seed для сэмплинга параметров;
- seed для noise/layout;
- seed для auxiliary-слоя.

Одинаковый seed + одинаковый конфиг = одинаковая сцена.

---

## 6. Что считать “ядром” проекта

Если кратко, ядро — это связка:

1. `ParameterSet` (управление вариативностью и зависимостями),
2. `FactoryGenerator` (layout + биомы + сборка),
3. `Scene`/`SceneObject` (иерархия сцены),
4. `ObjExporter` (финальная сериализация геометрии).

Именно эта связка превращает параметры в полноценную структуру завода.
